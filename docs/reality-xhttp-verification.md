# Reality и xHTTP: реализация и проверка

Проверено 1 октября 2026 года на существующих VMware ВМ OpenWrt 24.10
(opkg, 192.168.241.2) и OpenWrt 25 (apk, 192.168.1.1).

## Поведение

- При генерации исходящих Reality для стабильного sing-box-extended 2.7.2
  и новее автоматически добавляется `support_x25519mlkem768: true`.
  Проверяется версия Extended после `-extended-`, а не версия базового ядра.
  Для обычного sing-box, старого Extended, неизвестной версии и prerelease
  автоматическое добавление отключено. Явные `true` и `false` сохраняются.
- Импорт URL и Xray JSON принимает `uplinkHTTPMethod`/`uplinkHttpMethod`,
  `SessionIDPlacement`/`sessionIDPlacement`/`sessionPlacement`,
  `SessionIDKey`/`sessionIDKey`/`sessionKey`, `scMaxBufferedPosts`
  и соответствующие имена sing-box. Поддерживаются плоский query,
  URL-encoded `extra` и вложенные настройки xHTTP. Плоские значения имеют
  приоритет; нулевой `scMaxBufferedPosts` сохраняется.
- Экспорт ссылки, повторный импорт и генерация из ручной ссылки сохраняют
  эти четыре поля и явную настройку Reality. Исправлено преждевременное
  декодирование всей VLESS/Trojan-ссылки: закодированный `&` внутри значения
  больше не разбивает query.
- Старый кэш восстанавливает отсутствующие поля из сохранённой исходной
  `share_link` при совпадении адреса, порта, типа и учётных данных. Явные
  значения и идентичность узла сохраняются. Файлы переписываются атомарно
  только при изменениях, с правами 600. Формат производного runtime-кэша
  повышен с 10 до 11; постоянный кэш формата 9 сохраняется для работы офлайн.
- `sessionIDTable` и `sessionIDLength` автоматически не преобразуются:
  соответствие полей разных ядер не установлено. Явные нативные поля
  sing-box не удаляются. Если старый кэш уже потерял поля и исходную ссылку,
  восстановить их невозможно — нужна повторная загрузка подписки.

## Проверки

| Проверка | OpenWrt 24 | OpenWrt 25 |
| --- | --- | --- |
| `tests/reality_xhttp.uc`, 245 проверок | Пройдено | Пройдено |
| Импорт, экспорт, ручная генерация, генерация из старого кэша | Пройдено | Пройдено |
| Порог версии, явные true/false, отключённый Reality | Пройдено | Пройдено |
| Проверка конфигов настоящим Extended 2.7.2 | Пройдено | Пройдено |
| HTTP через VLESS + Reality + xHTTP GET/header | Пройдено | Пройдено |
| Xray подтвердил X25519MLKEM768 в TLS | Пройдено | Пройдено |
| Пакеты, конфигурация и состояние службы до/после | Совпадают | Совпадают |

Для обмена трафиком `tests/reality_xhttp_vm.sh` запускает самостоятельные
Extended 2.7.2 и Xray 26.9.8 с временными ключами только на loopback.
Конфиг клиента сначала создаёт настоящий генератор Forkop из ссылки.
Запрос идёт через SOCKS с отключённым обходом прокси для localhost;
проверяется ответ тестового HTTP-сервера и запись Xray о гибридном key share.
Новое правило Freedom в Xray разрешает только тестовый адрес 127.0.0.1:18090.
Процессы стенда завершаются после проверки. Пакеты, firewall и рабочие
конфиги ВМ не меняются.

Бинарники получены из официальных релизов; архив Extended проверен по SHA-256
`e94b7fab2562b15b6aff61d91b93be6ff3611f8709c63b38db79453bcf2c683a`,
архив Xray —
`a8c6d5b53957600d7e18d16e697201a4c942fe823307deb039bf8f40587aa556`.
