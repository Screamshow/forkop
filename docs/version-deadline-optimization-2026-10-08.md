# Прямое ожидание версии с deadline — 8 октября 2026

Следующее изменение установлено на 192.168.90.1 в локальную сборку Forkop 2.0.0, после native readlink.

## Реализация

В config/validator.uc bounded_command_output_from_args больше не запускает shell-цикл kill -0 / sleep 1. Команда выполняется через встроенный system(command, timeout_ms) ucode, с exec в оболочке, чтобы управляемый дочерний процесс был самой командой. По [документации ucode](https://ucode-lang.org/module-core.html#system) system ждёт завершения и принудительно завершает дочерний процесс SIGKILL при превышении таймаута.

Для check-requirements сохранены пять секунд deadline. Вывод принимается только при exit status 0; частичный вывод при ошибке/таймауте отбрасывается. Вывод хранится в уникальном закрытом временном каталоге; после завершения файл и каталог удаляются. При отсутствии fs.mkdtemp в старой библиотеке используется существующая mktemp -d. Новых пакетных зависимостей нет.

## Проверки

Новый tests/version_deadline.sh выполняет реальный helper:

- быстрый успешный ответ возвращается быстрее 0,8 с;
- shell-метасимволы и кавычки в аргументе передаются буквально;
- вывод команды с ошибкой не принимается;
- зависшая команда с частичным stdout завершается около заданного deadline;
- дочерний PID исчезает после возврата helper (процесс завершён и reaped).

Тест пройден локально, на OpenWrt 24, OpenWrt 25 и пользовательском ARM64 роутере. Локально также прошли sing_box_runtime и manual_restart_contract. Обе ВМ прошли check-requirements и полный restart с кандидатом; исходный validator восстановлен побайтно.

## Исследование DNS

На обеих ВМ исследован кандидат штатного dnsmasq reload с restart при ошибке вместо безусловного restart. Reload заново формирует конфигурацию через rc_procd start_service и затем сигнализирует dnsmasq. Локальные mock-тесты reload/fallback, существующие dns_apply и dns_rollback_transaction прошли.

Но интеграционная проверка выявила, что сразу после возврата reload локальный DNS ещё не слушает порт: dig получил connection refused при status dnsmasq=running. Это асинхронный переход, требующий отдельной проверки готовности. Кандидат не внедрён в production и полностью убран из рабочего dns/apply.uc. На роутере DNS не менялся. Обе ВМ восстановлены, Forkop запущен и работает. Экспериментальный тест сохранён только в tmp/optimization-review-20261008/version-deadline/dns_reload-experiment.sh.

Следующий участок работы — надёжное ожидание завершения DNS-перехода с проверкой успешного применения настроек и восстановления при отказе. Простая замена restart на reload пока недостаточна для текущего контракта готовности.
