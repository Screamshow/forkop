# Extended: ручная установка и откат на OpenWrt 25

Проверено 1 октября 2026 года на существующей VMware ВМ 192.168.1.1.
Перед изменениями сохранены пакеты, APK world, конфигурация, бинарник Tiny
и состояние служб. Использованы настоящие APK Extended 2.7.1 и 2.7.2.

## Ручное обновление и версия LuCI

Предыдущий Extended установлен через обработчик Forkop. Затем выполнен
ручной `apk add --allow-untrusted` пакета 2.7.2, как в обращении клиента.
Кэш API прогрет до установки; вручную он не удалялся.

- `sing-box version`: `1.14.1-extended-2.7.2`.
- `diagnostics/runtime.uc get-system-info`, поле `sing_box_version`:
  `1.14.0-extended-2.7.1`.

Баг воспроизведён. Сигнатура нового бинарника инвалидирует старый кэш,
но `sing_box_live_probe_disabled()` отключает чтение бинарника при отметке
`extended` или `extended-compressed`. API заново читает устаревший
`/etc/forkop/sing-box-version`. Следовательно, простая очистка кэша
при таком состоянии не исправляет отображение. Это отдельная ошибка;
исправление выбора пакета для отката в canary.5 её не устраняет.

## Исправление подготовки отката в canary.5

Использован настоящий `components/action.uc` из исходников canary.5:

| Сценарий | Результат |
| --- | --- |
| Штатное обновление Extended 2.7.1 → 2.7.2 | PASS, версия бинарника 2.7.2 |
| Сбой после успешной установки нового APK | PASS, обработчик вернул ошибку с подтверждением отката |
| Возврат точной предыдущей версии | PASS, установлен и запускается бинарник 2.7.1 |
| Восстановление исходной ВМ | PASS, Tiny 1.13.21, исходные пакеты, APK world и работающая служба |

Транзакции обновления и отката выполнялись с остановленным Forkop.
Настоящие `apk add`, `apk del`, чтение метаданных и откат не подменялись.
Релизные манифесты и пакеты обслуживал временный HTTP-сервер на loopback.
Сетевые `apk update` и скачивание исходного Tiny заменены локальными
фикстурами, поскольку внешний HTTPS из ВМ работал нестабильно.
Обёртка сбоя сначала выполняла настоящий `apk add` нового Extended,
затем один раз возвращала код 42. Операции чтения метаданных не затрагивались.

ВМ OpenWrt 24 не использована для полной установки: свободных 28 МБ
flash недостаточно для Extended. Ранее на ней прошли проверки
преобразования версии и выбора предыдущего релиза.

Рабочие журналы и снимки находятся на ВМ в
`/tmp/forkop-extended-rollback-test/`. Временный HTTP-сервер остановлен.

## Исправление отображения версии LuCI

В `diagnostics/runtime.uc` обычная отметка `extended` больше не запрещает
чтение версии установленного бинарника. Смена сигнатуры бинарника после
ручной установки инвалидирует кэш, и API получает актуальную версию.
Запрет запуска для `extended-compressed` и активной транзакции сохранён.

Повторная проверка 1 октября 2026 года на OpenWrt 25 с исправленным модулем
в отдельном каталоге `/tmp/forkop-luci-version-fix/lib`:

- Настоящая установка Extended 2.7.1 через обработчик и прогрев кэша API.
- Настоящий ручной `apk add --allow-untrusted` Extended 2.7.2.
- Бинарник и `sing_box_version` API: `1.14.1-extended-2.7.2` — PASS.
- Сохранённый `/etc/forkop/sing-box-version`: `1.14.0-extended-2.7.1`;
  ручной очистки кэша не было — PASS.
- `sing_box_extended` и `sing_box_tailscale`: `1` — PASS.
- Повторный запрос возвращает тот же закэшированный JSON — PASS.
- Исходные пакеты и APK world совпадают со свежим снимком перед тестом,
  SHA-256 исходного бинарника совпадает, конфигурация восстановлена,
  Forkop работает с Tiny 1.13.21 — PASS.

Журнал: `/tmp/forkop-luci-version-fix/result.log` на ВМ.
Установленные файлы Forkop не заменялись; исправление находится в исходниках.

## Ручная установка поверх старой отметки Compressed

Дополнительная правка учитывает, что управляемый Compressed устанавливается
без пакетов sing-box. Если появился `sing-box-extended`, `sing-box-tiny` или
`sing-box`, старая отметка `extended-compressed` больше не запрещает чтение
текущего бинарника и не задаёт признаки Compressed в API. В `singbox/runtime.uc`
исправлены также определение варианта, чтение версии и проверка Tailscale.
Для настоящего Compressed без пакета сохранено чтение файла версии.
Во время активной транзакции диагностика не запускает бинарник.

На OpenWrt 25 повторён настоящий APK-тест 2.7.1 → 2.7.2 с отметкой
`extended-compressed`, выставленной перед прогревом кэша. Бинарник и LuCI API
показывают `1.14.1-extended-2.7.2`, несмотря на старый файл версии — PASS.
Журнал: `/tmp/forkop-luci-version-fix/compressed-marker-result.log`.
ВМ снова восстановлена до Tiny 1.13.21; пакеты, APK world и SHA-256 бинарника
совпадают со свежим снимком перед тестом, Forkop работает.

Регрессионный тест `tests/sing_box_manual_version.sh` выполнен на ВМ с
изолированными фикстурами APK и OPKG. Проверены Extended, Tiny и обычный
sing-box при старой отметке Compressed, версия и признаки API, определение
варианта runtime. Проверено отсутствие запуска бинарника для настоящего
Compressed без пакета и для активной транзакции — PASS.

Тест не проверяет ручную замену распакованного/сжатого бинарника вне пакетного
менеджера: для Compressed без пакета источником версии остаётся файл состояния.
