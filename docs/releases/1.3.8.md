### Обновление списков

- Изменение локальных условий маршрутизации больше не запускает загрузку списков. Это относится к действию секции, устройствам и исключениям, интерфейсам, портам и порядку правил.
- Списки загружаются только при изменении состава источников, наступлении заданного интервала, ручном обновлении или отсутствии пригодного кэша.
- Перед применением Forkop X загружает и проверяет полный набор источников одной транзакции. Для встроенных списков при недоступности зеркала автоматически используются резервные адреса jsDelivr, GitHub Raw или upstream-репозитория. Если источник не удалось получить ни с одного доступного адреса либо полученные данные не прошли проверку, транзакция отменяется, а действующие rule-set и правила nftables остаются без изменений.
- Несколько изменившихся списков применяются одной транзакцией и вызывают не более одного итогового перезапуска sing-box.
- Повторное получение тех же данных не изменяет файлы rule-set, не перезапускает sing-box и не разрывает активные соединения.

### Перезагрузка и работа без сети

- Добавлен постоянный проверяемый кэш собранных списков и исходных данных для nftables.
- После перезагрузки последняя успешно сохранённая версия списков восстанавливается из кэша без обращения к сети.
- Время последнего успешно сохранённого обновления сохраняется при reboot.
- Повреждённый или устаревший кэш не применяется: Forkop запускается в безопасном режиме и пытается восстановить списки, сохраняя работоспособность sing-box и DNS.
- Общий постоянный кэш списков и удалённых rule-set ограничен 8 МБ. Новая версия записывается только в том случае, если после записи на flash останется не менее 8 МБ свободного места.
- Если места во flash недостаточно, обновление всё равно применяется из `/tmp` и работает до перезагрузки, а предыдущий пригодный постоянный кэш остаётся без изменений. В рамках текущего запуска роутера Forkop запоминает успешное обновление и не загружает те же списки повторно по расписанию. После reboot используется последняя сохранённая версия, а более новая версия будет повторно получена при наличии сети.

### Стабильность

- Обновление списков, изменение конфигурации и обновление удалённых rule-set синхронизированы. Запросы reload, поступившие во время загрузки и проверки источников, откладываются и объединяются в один итоговый reload, поэтому перезапуск sing-box больше не обрывает загрузку через секцию.
- Исправлена OOM-регрессия на роутерах с небольшим объёмом оперативной памяти: автоматическая проверка задержки больше не запускает массовую проверку всех прокси одновременно, объединяет повторные запросы и обрабатывает прокси небольшими пакетами.
- Проверка задержки синхронизирована с перезапуском Forkop X. Между пакетами она уступает ожидающему reload и безопасно прекращается, если sing-box был перезапущен.
- Изменение источников во время загрузки отменяет устаревшую транзакцию. Следующая попытка строится уже по новой конфигурации.
- При ошибке обработки транзакции списков восстанавливаются предыдущие rule-set и таблица nftables; отложенный reload выполняется только после успешного применения полного набора.
- Удаление последнего источника очищает его runtime-файлы и постоянный кэш без лишних сетевых запросов.
- Неиспользуемые файлы кэша удалённых rule-set и временные файлы прерванных загрузок автоматически очищаются без удаления данных, относящихся к активной конфигурации.
- Загрузки в `/tmp` ограничиваются по фактически записанному объёму и не могут занять последние 8 МиБ временного хранилища.

### Подписки и проверка задержки

- Обычное обновление списков и применение локальных настроек больше не запускают автоматическую проверку задержки.
- Автоматическая проверка задержки после обновления подписки выполняется только тогда, когда набор прокси действительно изменился.
