# Заключительные проверки исправлений — 1 октября 2026

Использованы существующие VMware ВМ: OpenWrt 25 (`192.168.1.1`, APK)
и OpenWrt 24 (`192.168.241.2`, OPKG). По просьбе пользователя резервные
копии ВМ не создавались, исходное состояние после тестов не восстанавливалось.
Перед изменениями записаны списки пакетов и состояние procd.

Из текущего рабочего дерева собраны две локальные тестовые версии
`1.14.9-canary.6` и `1.14.9-canary.7`. Это обозначения фикстур, а не
опубликованные релизы. Пакеты находятся в `dist/vm-release-baseline` и
`dist/vm-release-target`. Версия в сгенерированном исходнике LuCI возвращена
к `__COMPILED_VERSION_VARIABLE__`, чтобы сборщик корректно подставлял
версию каждого пакета вместо номера ранее установленной правки роутера.

## Результаты

| Сценарий | OpenWrt 25 | OpenWrt 24 |
| --- | --- | --- |
| Настоящий асинхронный restart из обработчика LuCI с двумя конкурентными reload и сохранённым pending-запросом | PASS | PASS |
| Завершение restart, отсутствие pending-маркера и runtime-lock, один управляемый sing-box, работающий DNS | PASS | PASS |
| Второй настоящий sing-box: отказ reload и restart, сохранение исходного PID и nft-политики | PASS | PASS |
| Неверный PID в представлении procd: отказ reload без изменения nft-политики и действующего процесса | PASS | PASS |
| Восстановление здорового состояния после завершения тестового второго процесса | PASS | PASS |
| Сбой после настоящей установки целевого Forkop: штатный откат пакетов и конфигурации, затем завершение pending reload | PASS | PASS |
| Настоящее обновление локальных пакетов .6 → .7 с pending reload | PASS | PASS |
| Актуальная версия и признаки Extended/Tiny/обычного sing-box при старой отметке Compressed, с фикстурами APK и OPKG | PASS | PASS |

Обёртки пакетных менеджеров выполняли настоящие APK/OPKG операции.
Сбой вносился только после установки целевого backend-пакета; операции
чтения метаданных не подменялись. После внесения сбоя тест изменял параметр
конфигурации, чтобы SHA-256 проверкой подтвердить её восстановление самим
обработчиком отката. Манифесты и архивы с SHA-256 обслуживал временный
HTTP-сервер на loopback ВМ. Для APK использован `--no-network`, чтобы
изолировать установку локальных архивов от внешних репозиториев.

На OpenWrt 25 первый запуск очереди столкнулся с недоступной загрузкой
Cloudflare и завершился fail-safe отказом восстановления списка. Перед
повторным запуском удалены внешние community lists из тестовой секции
`vm_test`, отключено периодическое обновление списков. Повторный тест прошёл.
Также устаревшая привязка Tiny по хэшу в APK world заменена на точную
установленную версию `sing-box-tiny=1.13.21-r1` для установки тестовых пакетов.

OpenWrt 24 не имеет Bash. Тест версий переведён на POSIX shell и повторён
на обеих ВМ. Установка Extended на OpenWrt 24 не выполнялась из-за ранее
подтверждённого недостатка flash; варианты проверены изолированными фикстурами.

## Интерфейс

Прошли 30 тестов Vitest и проверка TypeScript. Проверены подтверждение
устойчивого конфликта после повторных наблюдений за пять секунд, сброс
наблюдений при перезапуске и разрыве опроса, исчезновение подтверждённого
предупреждения после устранения конфликта. Проверка интерфейса здесь
автоматическая; отдельный визуальный прогон браузера на ВМ не выполнялся.

## Итоговое состояние

Обе ВМ оставлены на локальной тестовой сборке .7, с исходными вариантами
Tiny. Все три пакета Forkop имеют одну версию (.7; APK показывает `1.14.9_rc7`).
Итоговый API обеих ВМ: `running=1`, `restart_blocked=0`,
`status="running & enabled"`, `dns_configured=1`. Pending-маркер и
runtime-lock отсутствуют. Тестовые вторые процессы завершены, HTTP-серверы
остановлены. Пользовательский роутер в ходе этих проверок не изменялся.

Журналы на каждой ВМ: `/tmp/forkop-release-check/`.
Локальные копии ключевых результатов: `tmp/release-check-evidence/vm25/`
и `tmp/release-check-evidence/vm24/`.

Сценарии сохранены в `tests/release_queue_vm.sh` и
`tests/release_update_vm.sh`; они требуют `FORKOP_TEST_VM=1`, VMware,
подготовленных локальных пакетов/манифестов и тестов в `/tmp`.
Защита процессов дополнена прямой проверкой отказа restart в
`tests/singbox_single_process.sh`.

Дополнительных сбоев проверяемых исправлений не обнаружено.
