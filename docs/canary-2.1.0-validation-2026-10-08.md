# Проверка Forkop X 2.1.0-canary.1 перед canary — 8 октября 2026

## Итог

Подготовлены и проверены точные локальные APK/IPK 2.1.0-canary.1. Они установлены на обеих существующих ВМ и пользовательском роутере. Публикации, релиза на GitHub и синхронизации зеркала не было. Начат клиентский пилот: предоставленный пользователем Cudy WR3000S v1 прошёл проверку, см. [отчёт Cudy](cudy-canary-2.1.0-validation-2026-10-08.md). Остальные устройства пользователь предоставит отдельно.

Bytecode удалён из штатных build.sh и forkop/Makefile. Экспериментальные инструменты сохранены в tmp/optimization-review-20261008/bytecode-stage3/archived-tools, исходный compiler checkout и результаты сохранены. Backend остаётся текстовым. Порог возраста core — 8 секунд. Sing-Box X 1.0.1 не обновлялся; при чистой установке на ВМ повторно установлен тот же executable из проверенных пакетов зеркала.

## Сборка

- Frontend: TypeScript, tsup/AST equivalence, 559 тестов в 53 файлах прошли.
- build.sh создал шесть пакетов. Повторная сборка из отдельного чистого каталога исходников прошла; содержимое всех APK/IPK совпадает с тестируемыми пакетами. Архивы не побитово воспроизводимы из-за упаковочной метаинформации; повторные архивы не подменяют проверенный комплект.
- Выполнена настоящая SDK-сборка backend/LuCI/i18n штатными Makefile для OpenWrt 24.10.6 IPK и 25.12.3 APK. Собран host po2lmo. NO_DEPS=1 ограничил работу целевыми пакетами; зависимости/ядро OpenWrt не пересобирались. Это проверка SDK-пути упаковки, не сборка нового firmware.
- SDK обнаружил две реальные ошибки: generated не переносился в build directory LuCI; публичное canary.N имя не принималось APK. Исправлены копирование generated и преобразование package version в 2.1.0_rc1 для APK. Встроенная/отображаемая версия остаётся 2.1.0-canary.1, IPK сохраняет публичный формат.
- installer DHCP/ownership, shell inventory, subscription version snapshot, DNS config, version deadline и build-version проверки прошли. Первые host-запуски не находили ucode/libucode; исправлен только test environment через локальный wrapper, штатные файлы host ucode не менялись.

Артефакты: tmp/canary210-validation/packages; SHA256SUMS в этом каталоге; manifest.json рядом с ним содержит размеры, версии и хеши. sdk-packages — отдельные результаты SDK, clean-packages — результаты повторной сборки. Распространяемый кандидат — именно packages.

## Обе ВМ

До изменений сохранены package/service state, UCI и core hash. OpenWrt 25: 192.168.1.1; OpenWrt 24: 192.168.241.2.

Проверены:

1. Установка точного кандидата, точный откат к предыдущему локальному комплекту и повторная установка с настоящими package hooks.
2. Полный full_uninstall, отсутствие backend/core/config, чистая установка точных 2.1.0 пакетов и того же X. Пустая конфигурация не запускается; минимальная bypass-политика создаёт рабочие core/DNS. Затем исходная конфигурация восстановлена.
3. Обновление с опубликованного 2.0.0 через реальные package installation functions текущего install.sh; повторный вызов. APK реально переустанавливал пакеты, повторный IPK распознал up-to-date. Полный HTTP-сценарий установки неопубликованного релиза через зеркало пока невозможен и не заявляется.
4. Настоящий reboot каждого устройства с точным кандидатом. Boot ID изменился, версия 2.1.0-canary.1, один принадлежащий Forkop core, min_age=8, sing-box check, DNS и сохранённый executable hash подтверждены. Это функциональный reboot, не замер его ускорения.
5. LuCI: шесть вкладок, русский/английский интерфейс, редактор секции, реальное Save & Apply, подтверждение изменения через UCI и восстановление исходного файла. Page errors отсутствуют, временные ubus sessions уничтожены.
6. Повторная DNS failure matrix на финальных библиотеках: changed/unchanged config, несколько instances, port 1053/port=0/disabled, error/no-op/stopped reload с fallback, два отказа и два ложных успешных init action без готовности, recovery. Оба runner завершились RESTORED rc=0.
7. dont_touch_dhcp=1 через полный lifecycle restart восстанавливает прежние DNS-настройки; возврат к 0 снова применяет Forkop DNS. Исходная UCI восстановлена, оба теста DONT_TOUCH_DHCP_PASSED.

Границы и исправления тестов:

- На ВМ25 full_uninstall также удалил auto dependencies. Попытка чистой offline-установки закономерно не могла вернуть их. Зависимости загружены из штатных репозиториев; прерванная загрузка libopenssl повторена. Установка точного кандидата и fresh-config запуск затем прошли. Исходный offline runner и его неуспешная recovery не считаются успехом.
- Для baseline 2.0.0 на ВМ25 потребовался coreutils-base64, удалённый вместе с auto dependencies. Тестовые архивы получены с официального downloads.openwrt.org и проверены apk verify; ключ их подписи на ВМ не был доверенным, поэтому только эти тестовые зависимости установлены с allow-untrusted. В финальные Forkop пакеты они не входят.
- Маленькая ВМ24 заполнилась staging-копиями двух core-архивов. Именно созданный в этом тесте каталог core перемещён в /tmp, затем неполное staging повторено. Продуктовый install/space-check не объявляется причиной этого переполнения.
- Первый дополнительный dont_touch test ошибочно напрямую вызывал configure helper, который не является lifecycle owner этой настройки. Он отклонён; подтверждение получено повтором через публичный restart, как в прежних проверках.

Штатные dnsmasq init/DHCP восстановлены, временный reload_candidate и generated forkop_probe config/confdir удалены. В финале обе ВМ: 2.1.0-canary.1, running/enabled/DNS-configured, один core, исходная UCI и неизменный executable hash. Резервные копии остаются отдельно от production runtime.

## Парная серия на пользовательском роутере

Сравнивался опубликованный backend 2.0.0 с новым backend 2.1.0-canary.1. UI до финальной установки не менялся; он не входит в измеряемый CLI manual_restart. Все предыдущие оптимизации входят в различие с опубликованным backend. Старый исходный профиль 43,56 с уже включал первый этап и является другой точкой отсчёта.

Порядок A B B A A B, по три успешных полных manual_restart каждого варианта. Перед каждым замером — отдельный неучитываемый прогрев. Одинаковы UCI, executable core и min_age=8. Сеть оставалась живой, каждый timed вызов включал подготовку подписок/списков. Код 75 при занятом runtime lock отмечался и повторялся вне успешного замера; такие отказы не считаются ускорением.

| Порядок | Backend | Секунды |
| --- | --- | ---: |
| 1 | опубликованный 2.0.0 | 50,48 |
| 2 | кандидат 2.1.0-canary.1 | 28,93 |
| 3 | кандидат 2.1.0-canary.1 | 28,78 |
| 4 | опубликованный 2.0.0 | 49,35 |
| 5 | опубликованный 2.0.0 | 49,50 |
| 6 | кандидат 2.1.0-canary.1 | 28,03 |

Медианы **49,50 → 28,78 с**, разница **20,72 с / около 42%**. Это наблюдение на данном роутере, три вызова каждого варианта; не универсальный процент и не обещание boot-ускорения.

Для всех шести точек итоговые хеши SRS, содержимого list cache и JSON подписки совпали после исключения служебного last-success.timestamp. До/после некоторых вызовов JSON cache имел разные хеши; причины различия содержимого до обновления не доказаны. Не выдавать серию за полностью замороженный replay входов/сети. Детали: paired-content и data-fingerprints.json; секретные JSON/конфигурации не выгружались.

Неуспешные первые runner исключены: неограниченное предположение о немедленной готовности после фонового перехода, отсутствие повтора busy/75 и конфликт каталога extraction. После завершения всех шести измерений обнаружена ошибочная финальная wait-конструкция самого profiling runner. Runner остановлен после завершения пакетной операции; отдельный final-confirm повторно установил и полностью проверил кандидат. Воспроизводимый локальный router-paired.sh исправлен. Измеренные интервалы находятся до этой финальной конструкции и не пересчитаны.

После финальной установки подтверждены точные payload backend/LuCI, исходные UCI/core hash, один core, min_age=8, DNS, HTTPS через SOCKS (204), running/enabled/DNS-configured. Отдельный zapret-manager сохранил nfqws PID 2809/2810. Роутер не reboot. Backup/rollback/state snapshots находятся в /root/forkop-canary210-paired5; прежние попытки сохранены отдельно. Старые /tmp backup присутствовали при начале работы.
