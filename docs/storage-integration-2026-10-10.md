# Проверка упрощённой установки и обновления, 2026-10-10

Проверены существующие VMware OpenWrt 25 (APK) и OpenWrt 24.10 (IPK).
Снимки VMware не создавались. Перед изменениями сохранены списки пакетов,
состояние служб и UCI в тестовый каталог. Публикация релиза не выполнялась.
Локальный кандидат: 2.1.2-canary.1; X: 1.0.3; Extended: 1.14.1-extended-2.7.2.
Пакеты обслуживались локальным HTTP через SSH, с исходными зеркальными
идентификаторами, проверкой длины и SHA-256.

## Результаты

- OpenWrt 25: установки, повторные установки и переходы между X, Extended
  и Extended Compressed прошли. Проверены возврат X после ошибки установки,
  ошибки запуска Extended Compressed и нехватки flash после удаления X.
  Конфигурация, DNS и единственный процесс sing-box восстановлены.
- OpenWrt 25: реальное обновление Forkop, откат после искусственной ошибки
  уже установленного пакета и повторный запуск общего установщика без stdin
  прошли. Вариант X сохранён.
- OpenWrt 24: с исходными примерно 15 МиБ свободного flash обычный Extended
  корректно отказался устанавливаться и восстановил X. После удаления X
  доступно 25300 КиБ, требование Extended — 104867 КиБ.
- Для Extended Compressed требовалось 25579 КиБ: исходного flash не хватило
  на 279 КиБ, X восстановлен. После освобождения старых тестовых файлов
  установка Compressed и обратный переход на X прошли.
- На малой VM проверены повторная установка X и восстановление после
  искусственной ошибки пакетного менеджера и нехватки flash.
- OpenWrt 24: реальное обновление Forkop и откат после ошибки установки
  прошли. Повторный общий установщик без stdin завершился успешно;
  окончательная проверка подтвердила рабочий DNS, один процесс X и сохранённые
  пользовательские настройки. Немедленная проверка после скрипта попадала
  в период асинхронного восстановления службы.
- Shell/ucode проверки расчётов, потоковой распаковки, ограничения загрузки,
  совместимости установщика и откатов прошли; `git diff --check` чистый.

## Ограничение RAM

На OpenWrt 24 доступно ядру 207096 КиБ RAM, swap отсутствует. При установке
Extended Compressed со старыми файлами в tmpfs воспроизведён OOM во время
запуска бинарника для проверки версии: ядро убило sing-box с anon RSS
52352 КиБ. Установка вернула рабочий X. После очистки старых временных файлов
повторная установка прошла без нового OOM.

Потоковая распаковка устраняет несжатую копию бинарника в tmpfs, но не RAM,
которую UPX требует для запуска. Проверка свободной памяти для загрузки
с резервом 8 МиБ не гарантирует отсутствие OOM при исполнении Extended.
Безусловную готовность стабильного релиза для роутеров с 256 МиБ утверждать
нельзя. VMware x86/64 также не проверяет особенности UBIFS и ARM.

Логи и состояние находятся в `tmp/storage-integration-20261010` локально и
`/tmp/storage-integration-20261010` на VM. Поле UCI `shutdown_correctly`
меняется службой при запуске; `update_channel` меняется установщиком с
`--channel canary`. Они исключаются из сравнения пользовательских настроек.
